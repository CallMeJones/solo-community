# Solo Trademark Policy

The Solo source code is licensed under Apache-2.0. The "Solo" name and
the Solo logos are not. This policy explains what you can and cannot do
with the Solo marks.

## Marks covered

- The word mark **"Solo"** as used to refer to this project, its binary,
  its services, and its documentation.
- The Solo logo (when one is published).
- The visual identity of the Solo project (color palette, typography
  treatments) when used as a project identifier.

These are referred to collectively as the "Solo Marks."

## What you can do without permission

You may use the Solo Marks in the following ways without asking:

1. **Refer to the project factually.** "I use Solo." "Solo is a local-first
   memory daemon." "This article compares Solo and Mem0." Standard
   nominative use is fine.
2. **Link to the project.** Any direct link to the Solo source repository,
   documentation, or release pages.
3. **Distribute unmodified Solo binaries.** If you redistribute Solo as
   built from an official release tag — Homebrew formula, Linux distro
   package, container image — you may use the Solo name and logo to
   identify the binary, provided you make no modifications to the binary
   or the marks. Modifications must follow the rules in the next section.
4. **Discuss, criticize, or review the project.** Free expression is
   protected; this policy does not restrict commentary.

## What requires permission or modification

The following uses are restricted to protect users from confusion:

1. **Modified binaries.** If you fork Solo, modify it, and distribute the
   result, you must not call your fork "Solo" or use the Solo logo. You
   may say "based on Solo" or "fork of Solo" in factual descriptions, but
   the project itself must use a different name.
2. **Hosted services.** If you run Solo (or a fork) as a hosted service
   for third parties, you must not market that service as "Solo" or use
   the Solo marks as the primary identifier of your service. You may
   factually state "powered by Solo" if and only if the underlying binary
   is unmodified Solo from an official release.
3. **Domains, packages, and project names.** You may not register
   domain names, package registry namespaces (npm, crates.io, PyPI, Docker
   Hub), social media handles, or organization names that are confusable
   with "Solo" without prior written permission.
4. **Merchandise.** Stickers, t-shirts, or other physical merchandise
   bearing the Solo marks for sale require written permission.

## How to ask

If your intended use falls outside the unrestricted list above, or if
you're not sure, contact the project at [trademarks@solo.dev — placeholder
until a real address is set up] before using the marks. Permission is
generally granted for good-faith uses that don't risk confusing users
about the source or quality of the software.

## Why this policy

This policy is modeled on Bitwarden's trademark policy and serves the
same purpose: keep the source code maximally permissive (Apache-2.0) so
the project gets adopted, while preventing forks or unrelated services
from impersonating the project. The Apache-2.0 license explicitly does
not grant trademark rights (License §6) — this document defines those
rights separately.

## Updates

This policy may be updated. Material changes will be announced via the
project's release notes. The version of this policy in effect at the
time you began a particular use of the Solo Marks governs that use.
