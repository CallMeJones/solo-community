# Solo 0.12.8

A library that would not open, opens again.

Four faults could each leave an install stuck on *Unlock your library* with
nothing to go on. 0.12.7 fixed the worst of it — the window now shows the
daemon's own error instead of `ExitStatus(1)`. This release fixes the three
underneath, and adds somewhere to turn when it happens.

## Fixed

- **`migrate-embedder` blocked itself.** It copied the search-index snapshots
  and left the originals in place, then reopened the library under the new
  embedder — which is exactly what those snapshots refuse. The migration died
  with *HNSW snapshot dim (384) does not match solo.config.toml embedder.dim
  (768)* and left you to delete the files by hand. They are now cleared as
  soon as the backup is safe. The backup stays, for rollback.

- **A library written by an older Solo had no way home.** The packaged model
  keeps its name and its 384 dimensions between versions but changes identity,
  and a library remembers the identity it was written with — so Solo refused
  it, and the only route out was to move the library to Ollama and keep Ollama
  running forever. **`solo migrate-embedder bundled`** re-embeds it with the
  model this Solo packages, through the same backed-up sequence as the Ollama
  path. Your memories are kept.

- **A wrong passphrase read like a broken file.** SQLCipher decrypts the first
  page with the wrong key, gets noise, and SQLite reports that the noise is not
  a database — so the error said *set journal_mode=wal: file is not a
  database*, and people went looking for corruption. It now says **that
  passphrase does not open this library**, keeping the original text in
  brackets for support.

- **Error messages named commands that could not help.** The two embedder
  refusals pointed at `solo reembed`, which cannot run while the snapshots it
  would rebuild are what is blocking the open, and at `solo init --force`,
  which clears the refusal by starting an empty library. Both now name
  `solo migrate-embedder bundled`.

## Added

- **Solo Controls: "If Solo will not open".** A section beside Updates and the
  passphrase box, listing what each failure means and the command that answers
  it — including reading back the passphrase Solo saved for you, which Windows
  Credential Manager stores but offers no way to show. It sits there rather
  than in the Solo web app on purpose: that page is part of Solo Controls and
  opens even when the daemon will not start, which is the only moment it
  matters.

## Install

Windows: press **Check for updates** in Solo, or run
`SoloSetup-0.12.8-x86_64.exe`. It installs per-user, without an administrator
prompt. This release ships for Windows only; Ubuntu stays on 0.12.3.

Every package ships a `.sha256` beside it. These installers are not
code-signed, so Windows shows its unknown-publisher prompt.
