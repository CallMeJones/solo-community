# Solo 0.12.11

Solo's client setup now installs automatic memory recall, and update checks
correctly select the newest release.

## Added

- **Automatic recall as part of client setup.** Connecting Claude Code, Codex,
  or Gemini CLI installs hooks that retrieve relevant Solo memory at session
  start and before each prompt. Cursor receives asynchronous session-start
  context. VS Code Copilot receives session-start context in both the Copilot
  and Local runtimes.
- **Managed installation and removal.** Setup preserves other client settings,
  backs up changed files, and updates Solo hooks without duplicates. The
  `--no-hooks` option removes only Solo's hooks. Client verification reports
  whether the definitions are installed.
- **Bounded, read-only retrieval.** Hooks continue without Solo if it is offline
  or unavailable. They do not save conversations or change native memory
  settings. Current instructions take precedence over retrieved history.

Start Solo, choose the client in Connected Tools, and restart that assistant.
Review any trust request it presents; Codex exposes hook review in `/hooks`.
Existing connections need setup run again to install the hooks. Ordinary
Claude Desktop and web chat retain MCP access but do not support these lifecycle
hooks. See [client setup and coverage](../client-memory-hooks.md) for details.

## Fixed

- **Check for updates offered an older release once version numbers reached
  two digits.** Solo took whichever release GitHub listed first. GitHub orders
  releases by creation date, and in a repository that only carries releases
  every tag points at the same commit — so they all share a date and the order
  falls back to sorting tag names as text, where `pro.10` lands below `pro.2`.
  A machine running `pro.9` was told it had the newest build there was.

  Solo now orders releases by the numbers in their tags, so `0.12.10` is newer
  than `0.12.9` and `pro.10` is newer than `pro.9`, whatever order they arrive
  in.

  Community releases were never mis-ordered — their tags sit on real, separate
  commits — but the same code served both, so both are fixed.

- The update-order regression test now supplies both Windows and Linux package
  fixtures, fixing the previous Linux CI failure.

## Install

Windows: press **Check for updates** in Solo, or run
`SoloSetup-0.12.11-x86_64.exe`. It installs per-user, without an administrator
prompt. This release ships for Windows only; Ubuntu stays on 0.12.3.

Every package ships a `.sha256` beside it. These installers are not
code-signed, so Windows shows its unknown-publisher prompt.
