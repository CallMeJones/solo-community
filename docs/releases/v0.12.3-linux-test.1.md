# Solo 0.12.3

Community hardening, a rebuilt Memories workspace, and the security fixes
below.

## Memories

- A rebuilt workspace: memories open as a browsable list, with the 2D and 3D
  graphs as views onto the same scope rather than the only way in. Search,
  filters by source and age, and group navigation sit in one control row.
- A **Labels** switch beside the view buttons turns the names painted beside
  the 2D graph nodes off. On a library of any size they overlap into a wall
  of text; without them the shape of the graph is legible. The choice is
  remembered, and hovering a node still names it.

  The switch shipped in 0.12.2 on the old toolbar, which this workspace
  replaced. If you turned labels off there and then lost the control, this
  release gives it back.

## Hardening and fixes

- Reject foreign browser origins and unsafe Host headers before HTTP or MCP actions run.
- Keep lexical search available when the configured embedding service is unavailable, with an explicit warning.
- Remove exclusively attributed documents and retained originals during principal erasure; refuse ambiguous shared ownership.
- Add `solo gdpr audit` to report unattributed legacy memories and document chunks without guessing their owners.
- Fix the attachment tool schema that caused Claude to reject the entire MCP tool catalog. Argument validation remains on the server.
- Make first-run client checks truthful and explain save, recall and correction across two assistants.
- Provide a shared recovery-backup entry point that preserves the matching encryption configuration under the library lock.
- Extract browser policy, asset file operations and window navigation into focused modules without changing transaction ownership.
- Update vulnerable h2, Browserslist and selector-parser dependencies, enforce web dependency audits, and align the TypeScript starter version.
- Require full Community CI before release workflows and capture Windows API process failures with a pinned, signed Microsoft diagnostic tool.

The [benchmark report](../benchmarks/2026-09-08-longmemeval.md) measures session retrieval, not answer accuracy. Principal erasure does not erase external backups, exports or unknown-owner records. Back up your library before upgrading and retain its passphrase and configuration.

Live validation: Claude Code saved and corrected a synthetic fact; fresh Codex CLI sessions recovered each value. The corrected fact survived encrypted backup and restore. Browser workflow and accessibility checks passed on desktop and mobile. These checks do not establish compatibility with every client version or deployment.

## Verifying a download

Every package ships a `.sha256` beside it. These installers are **not**
code-signed, so Windows shows its unknown-publisher prompt; compare the
checksum if you want to confirm what you downloaded. Nothing in this release
should be described as signed.

## Install

Windows: run `SoloSetup-0.12.3-x86_64.exe`. It installs per-user, without an
administrator prompt.

Ubuntu 24.04 x86-64: `sudo apt install ./solo-0.12.3-ubuntu24.04-amd64.deb`
