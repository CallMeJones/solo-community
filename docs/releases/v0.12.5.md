# Solo 0.12.5

Updates are back in the Solo window.

## Updates

- **Settings → Updates, unlock & startup** (or the tray menu's **Updates &
  device settings**) now has an **Updates** section: choose an **Edition**,
  press **Check for updates**, then **Install**. Solo downloads the package,
  checks it against the `.sha256` published beside it, closes, updates and
  reopens. 0.12.4 had the update controls only in the old recovery window.
- **Edition** follows the Solo you have installed until you change it.
  **Pro** offers the newest Solo Pro build from its public release page;
  **Community** offers Solo Community again. Either one installs over the Solo
  you have, in place, and keeps your Memory Library. Picking an edition only
  chooses which package is downloaded: a Pro build verifies its own licence,
  and without one it runs exactly as Community.

## Solo account

- When the Solo you are running offers a Solo account (Solo Pro does), the
  same page shows who this machine is signed in as and a **Sign in to your
  Solo account** button. Signing in happens in your browser; Solo restarts by
  itself once you approve. Community has no account, so for it nothing
  appears.

## Updating from 0.12.3 or 0.12.4

Those versions have no update button in the Solo window. Either download
`SoloSetup-0.12.5-x86_64.exe` below and run it, or quit Solo from the tray and
start `solo-tray.exe --legacy-controls` from the install folder, then use
*Check for updates* there once.

## Verifying a download

Every package ships a `.sha256` beside it. These installers are **not**
code-signed, so Windows shows its unknown-publisher prompt; compare the
checksum if you want to confirm what you downloaded.

## Install

Windows: run `SoloSetup-0.12.5-x86_64.exe`. It installs per-user, without an
administrator prompt. This release ships for Windows only; Ubuntu stays on
0.12.3.
