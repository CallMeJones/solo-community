If Solo will not open

The line at the top of this window is Solo’s own reason for stopping. Find it below. Quit Solo first, then run the command in PowerShell.

“that passphrase does not open this library”

The passphrase is wrong; the library itself is fine. If you ticked “Remember on this device”, Solo saved it in Windows Credential Manager, which offers no way to show a saved password. This reads it back:

Add-Type @'
using System;
using System.Runtime.InteropServices;
public class SoloCred {
  [DllImport("advapi32.dll", CharSet = CharSet.Unicode, SetLastError = true)]
  static extern bool CredReadW(string target, int type, int flags, out IntPtr cred);
  [DllImport("advapi32.dll")] static extern void CredFree(IntPtr buf);
  [StructLayout(LayoutKind.Sequential, CharSet = CharSet.Unicode)]
  struct CREDENTIAL {
    public int Flags; public int Type; public string TargetName; public string Comment;
    public long LastWritten; public int CredentialBlobSize; public IntPtr CredentialBlob;
    public int Persist; public int AttributeCount; public IntPtr Attributes;
    public string TargetAlias; public string UserName;
  }
  public static string Read(string target) {
    IntPtr handle;
    if (!CredReadW(target, 1, 0, out handle)) { return null; }
    try {
      CREDENTIAL c = (CREDENTIAL)Marshal.PtrToStructure(handle, typeof(CREDENTIAL));
      return Marshal.PtrToStringUni(c.CredentialBlob, c.CredentialBlobSize / 2);
    } finally { CredFree(handle); }
  }
}
'@
[SoloCred]::Read('daemon-passphrase.solo-tray')
“this library was made with…” or “the search index was built for…”

An older Solo wrote this library with a different embedding model. Your memories are intact — this re-embeds them with the model this Solo packages and keeps everything. It can take a while on a large library.

& "$env:LOCALAPPDATA\Programs\Solo\solo.exe" migrate-embedder bundled
“configured embedder ollama:… does not match”

This library embeds through Ollama, so Ollama has to be running whenever Solo runs. Start it and open Solo again. To stop depending on it, use the packaged-model command above instead.

ollama serve
None of these match

Rename your library folder rather than deleting it, then open Solo and create a new one. The old library stays openable if the passphrase turns up later. Never delete it — a renamed folder can be put back.

Rename-Item "$env:USERPROFILE\.solo" ".solo-old"
